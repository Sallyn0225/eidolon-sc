# 卡牌、剧情标题和衣装的目录先从登录后的游戏查，ShinyColorsDB 只补缺

ADR-0032 给剧本和立绘文件加了官方资源服务器这条后备，但「有哪些卡、每张卡有哪些剧情、叫什么，有哪些衣装」仍然只来自 ShinyColorsDB 的 API。API 一停，同步就不知道该拉什么，新卡进不来。实测游戏不登录也能拿到资源清单（`/assets/asset-map-<哈希>`，39 万条路径），能知道有哪些文件，但没有名字；第三方目录 `service.sc-viewer.top/name` 有卡名和标题，可它也是志愿者站，也没有衣装名。我们要真名字，所以用一个游戏账号登录，从游戏自己那里查。

游戏的接口不是普通 HTTP：请求先由 WebAssembly 模块加密、整包 POST，会话号每次响应都换，请求头带着随客户端版本变化的版本号，响应头还有封号标记。在服务器上另写一个客户端既脆弱，也容易被认出不是正常客户端。所以让真正的游戏去跑：`frontend/scripts/game-catalog.mts` 用 Playwright 加载存下的登录态，在无界面的 Chromium 里打开游戏，进到 HOME，再从游戏的模块加载器里认出接口模块，用它发 GET。加密、会话、版本号都由游戏处理，请求排进游戏自己的队列，和玩家在 P デスク里翻卡、看衣装时发的一样。每周大约 40 个固定请求（角色、28 位偶像的卡、相册、衣装），外加最多 40 张卡的剧情查询（新卡优先，查过且卡没变的不再查），间隔至少 1 秒，只发 GET。

查到的写成 `corpus/game/catalog.json`。剧情同步和立绘拉取在它 3 天内更新过时，先从这里取卡牌、剧情和衣装，再照样问 ShinyColorsDB 的 API，补上游戏目录没有的（はづき的卡、还没查剧情的卡）；这时 API 出错只提示，不算同步失败。目录更旧（登录态失效、维护）或读不了时只问 API，并提示管理者。剧本和立绘文件照旧先问镜像、再问官方（ADR-0032）。名字按 ShinyColorsDB 的写法存（去掉姓和名之间的空格），出处名和 SCTranslationData 的目录名对得上，汉化版取代原文剧情、已有的剧情和衣装都不受影响。已经拉过的衣装保留清单里原来的名字和分类；新衣装的分类沿用同一衣装系列（游戏的 `groupId`）在清单里的分类，ShinyColorsDB 的这套分类是按系列手工分的，游戏里没有，全新的系列记为 `Special`。活动名的先后是：对照表、SCTranslationData 的目录名（同一活动的原文剧情和汉化版放在一处）、游戏相册里的活动名。

## Considered Options

- **只用免登录的资源清单，名字用占位或 sc-viewer 补**：不碰账号；但新卡、新衣装的名字只能占位，sc-viewer 停了就只剩占位，用户不接受。
- **在服务器上逆向游戏的接口，直接用 Python 调**：不用浏览器、更快；但要跟着游戏的 WebAssembly、版本号和平台登录一起改，而且客户端特征不对，更容易被封号。
- **游戏目录只在 ShinyColorsDB 挂了时才用**：账号用得最少；但这条路平时不跑，坏了要等用到时才发现，也拿不到 ShinyColorsDB 还没收录的新卡。
- **游戏目录新鲜时完全不问 ShinyColorsDB**：请求最少；但はづき的新卡、还没查剧情的卡，在 ShinyColorsDB 还活着时也进不来。

## Consequences

- 每周用一个游戏账号自动登录一次（两个同步脚本都会调用，两天内查过的不再查）。这比 ADR-0004、ADR-0032 更直接地碰到 enza 利用规约第 9 条，可能被封号，所以用一个不拿来玩的账号：一个账号同一时间只能在一处登录，这里一登录，别处就会掉线。
- 登录态是 Bandai Namco ID 的 cookie，实测有效 400 天，每次运行后存回去。要在有桌面的电脑上 `npm run game:login` 登录一次，再把 `game-login.json` 拷到服务器；它就是账号凭据，不进仓库。失效后同步退回 ShinyColorsDB，日志里会说要重新登录。
- 运行 `game:catalog` 的机器要有 Node.js、frontend 的依赖和 Playwright 的 Chromium（立绘同步本来就要这些），一次大约 1 分半钟，下载约 8 MB。
- P デスク只列 28 位偶像：はづき的 S 卡和【推しの子】联动卡不在里面。ShinyColorsDB 还在时由它补上；它停了以后，新出的はづき S 卡剧情就进不来了。她的衣装在衣装列表里，不受影响。
- 卡的剧情要一张一张查，第一次只查最新的 40 张，其余的每周接着查，还没查的卡由 ShinyColorsDB 补。新部署又碰上 ShinyColorsDB 已经停了时，可以手动 `npm run game:catalog -- --max-cards 2000` 一次查完（约半小时）。
- 游戏改了模块的写法、认不出接口模块时，`game:catalog` 以退出码 3 结束，同步退回 ShinyColorsDB；要照着游戏新的代码改认模块的字样。认不出资源清单模块时，游戏目录里的衣装这次都不拉，只拉 ShinyColorsDB 列出的。
- 相册里的培育剧情（W.I.N.G. 等）、特别剧情这次没接，仍然只来自 ShinyColorsDB 2024 年 3 月以前的相册。
- 游戏停服时游戏和官方资源服务器都会消失，这条路也就断了，那时只剩已经同步进库的剧情和拉到的立绘。
