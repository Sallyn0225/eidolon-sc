# 天气和日程按需查看：平时不放进「此刻」，问到时她自己看；用户看得到她在看什么

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「此刻」「日程」「工作」「时间段」「回合」「通话」「搭话」「光顾」「朋友圈」。说此刻、日程、工作、查看（她在回合里自己去看天气、翻日程、回忆剧情），不说工具调用、函数调用、渐进式加载（这些只在实现里用）。依据是对照实验（`research/on-demand-context` 分支，提交 4fdbc270，`.scratch/on-demand-context/findings.md`）：deepseek-flash 上，现在的做法闲聊时 40% 的回复提到日程，8 段对话里 7 段提了两次以上；按需的做法降到 8%、没有一段提两次以上，被问到时 20 次里 19 次调了对的查看、答得一样对或更对，代价是被问到的那回合首字慢约 0.8 秒。前端先读 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准；给用户看的文案要少。

## Problem Statement

- 她这周和下周的整张日程每回合都在「此刻」里。模型面前摆着它，就总想用上：闲聊时不停地说「今天拍了杂志、换了好几套衣服」，同一段对话里说两三遍，聊天显得死板。提示词里「只在相关的时候提起……说过就不再主动提」压不住。
- 天气也每回合都在里面，靠「平时不要主动提」「已经聊过就不要再提」压着。实验里天气压得住，但「这段对话里聊没聊过」全靠模型自己记，这是它最不擅长的；这几句约束本身也占地方。
- 她回忆剧情时，界面上只有一个转圈，用户不知道她在做什么，以为卡住了。往后她能自己去看天气、翻日程，等待的时候更需要让用户知道她在干嘛。

## Solution

- 打字和通话的回合里，「此刻」不再带整张日程，只带「现在正在做的那项」（它决定她此刻的状态：抽空回、在休息）。其余的她要「翻日程」才知道：制作人问起她的安排、忙不忙、哪天有空，或者话题真用得上时，她自己去看。
- 天气只在她可以主动提的时候放进「此刻」（隔了一阵再开口、天气显眼、制作人那边有预警，照现在的判定），而且同一段连着的往来里每一边只放一次，由服务器记，不再靠提示词说「聊过就别提」。其余回合她要「看天气」才知道。
- 「此刻」里加一句：天气和日程要看一眼手机才知道，问起或话题需要时去看，不要凭印象说（推了天气的那回合只说日程）。
- 她去看的时候，对话里那条还没说完的回复显示「真乃正在看天气」「真乃正在翻日程」「真乃正在回忆」，通话层里也显示；她说出话来提示就没了，不存进对话记录。现有的回忆剧情一起补上。
- 搭话、光顾、朋友圈照旧，不给她查看。

## User Stories

1. 作为制作人，我想和她闲聊时她不会每句都绕回今天的工作，这样聊天不死板。
2. 作为制作人，我想同一段对话里她不把同一项工作反复说好几遍，这样她像记得自己说过什么的人。
3. 作为制作人，我想问她「明天有工作吗」时她能答对，包括「明天没有安排」，这样我能信她说的日程。
4. 作为制作人，我想问「这周六晚上有空吗」时她按日程答，排了看电影就说排了看电影，这样日程和她说的话对得上。
5. 作为制作人，我想问「最近忙不忙」时她会去翻日程再答，说的是真排了的工作，不是编的。
6. 作为制作人，我想话题真用得上时（比如我问她最近有什么开心的事、我说周末宅家）她会自己去翻日程，这样她提起工作是因为相关，不是因为摆在眼前。
7. 作为制作人，我想她此刻正在做某项工作时，她一开口就带着这个状态（抽空回、在休息），不用我先问。
8. 作为制作人，我想问「东京今天天气怎么样」时她去看一眼再答，说的和实际一致。
9. 作为制作人，我想问「我这边冷不冷」时她看的是我档案里那座城市的天气。
10. 作为制作人，我想她看不到天气时（服务取不到）坦白说没看到，不编一个。
11. 作为制作人，我想我隔了好久才来、或今天天气变化大、或我那边有预警时，她仍会主动关心一句天气，这样她像惦记着我的人。
12. 作为制作人，我想她主动提过一次天气后，这段连着的往来里不再反复提。
13. 作为制作人，我想东京那边能提而我这边不能提时，她只会主动提东京的，和现在一样。
14. 作为制作人，我想隔了一阵（三小时以上）再来时，天气显眼的话她可以再主动提一次，这是新的一段往来。
15. 作为制作人，我想她在通话里也一样：被问到才去看，平时不反复提。
16. 作为制作人，我想她去看天气、翻日程、回忆剧情时，界面上告诉我「真乃正在看天气」之类，这样我知道她没卡住。
17. 作为制作人，我想她已经说了半句、接着去看东西时，提示出现在她已经说的话下面，说出下一句时消失。
18. 作为制作人，我想她同时看两样时（比如天气和日程），提示把两样都写上。
19. 作为制作人，我想打电话时通话层里也显示「真乃正在看天气」，这样电话里那一两秒的停顿有个交代。
20. 作为制作人，我想这类提示不留在对话记录里，刷新或回看历史时不会看到一串「正在看天气」。
21. 作为制作人，我想她说「我看了一下」这类话时自然，不提工具、记录这些词。
22. 作为制作人，我想她回复里永远不会出现奇怪的标记或代码，这样不出戏。
23. 作为用读屏器的制作人，我想「真乃正在看天气」能被读出来，这样我也知道她在做什么。
24. 作为制作人，我想她主动搭话时还是可能聊到今天的工作或天气，和现在一样，因为搭话本来就要找话头。
25. 作为制作人，我想酒吧和朋友圈里她的表现不变。
26. 作为制作人，我想打断她的时候（通话里我一开口），她正在看的东西也一起停下，和现在打断回复一样。
27. 作为自带 LLM 的用户，我想用我自己的模型时这些照样能用，因为保存自带 LLM 时已经检查过它会调工具。
28. 作为部署者，我想关掉日程时她不再有「翻日程」，「此刻」里那句提示也不提日程。
29. 作为部署者，我想没有天气服务时她不再有「看天气」，提示也不提天气。
30. 作为部署者，我想服务商缓存照样命中，查看的列表每回合都一样，开着的功能不变时不跳。
31. 作为部署者，我想服务重启后最多让她多主动提一次天气，不会因此出错。
32. 作为维护者，我想「她平时不知道、要看了才知道」这条规矩记进 ADR，以后加别的信息时照这个判断：要她主动说的推，被问到才说的让她看。
33. 作为维护者，我想 `GLOSSARY.md` 的「此刻」写明日程和天气现在怎么告诉她，并有「查看」这个词。

## Implementation Decisions

- **「此刻」分场合改**（`her_now` 的场合表）：打字和通话两个场合，日程只带正在进行的那项（用现在的写法和「说话可以带着这个状态」那句），不带本周其余和下周的、不带「做完了」的；天气只在可以主动提时带。搭话、光顾、朋友圈三个场合原样不动。制作人在哪座城市那一句照旧每回合都带（不在这次范围里）。
- **天气什么时候推**：沿用 `her_weather` 现在对每一边「能不能主动提」的判定（隔了 `LONG_APART`、`Today.stands_out`、预警），不改阈值。新加一条：同一段连着的往来里，每一边推过一次就不再推。「一段连着的往来」从上一次隔了 `LONG_APART` 以上的往来之后算起，和现在 `last_apart` 的口径一致（通话里算到接通前）。推过没推记在进程内存里，按对话和那一边记推的时间，不加表、不写库；重启后丢了，最多再推一次，可以接受。推了的那回合带「可以当个话头……提一次」那句；「已经聊过就不要再提」由服务器保证，提示词里这半句可以去掉。不能主动提的那一边不推，`KEEP_IN_MIND`「只是让你心里有数」那句不再出现在打字和通话里。
- **两项查看**，和回忆剧情并列交给对话模型：
  - 看天气：没有参数。返回东京和制作人那边今天的天气、预警，就是现在「此刻」里那几行，不带「能不能主动提」那句；取不到时返回「现在看不到天气」，并说不要编、可以说没看到。等的上限照现在的 `WAIT`。描述写明问起天气、冷暖、要不要带伞，或话题真需要时用，闲聊时不需要。
  - 翻日程：没有参数。返回现在 `schedule_lines` 给的整段（本周和下周、做完没有、那几条规矩）；没有安排时说这两周没有安排。描述写明问起安排、忙不忙、哪天有空，或话题真需要时用。
  - 名字用英文小写（实验里是 `look_up_weather`、`look_up_schedule`），描述和返回用中文。实验里的措辞是对着真模型试过的，照用；改了要重新对真模型试。
- **「此刻」里的提示句**：给了查看就加一句，实验里验证过的写法是「今天的天气和你这周、下周的日程，你要看一眼手机才知道：制作人问起或话题需要时用工具查，不要凭印象说。」推了天气的那回合只说日程；只给了其中一项时只说那一项。
- **查看列表每回合不变**：回忆剧情（有检索时）、看天气（有天气时）、翻日程（日程开着时），顺序固定，照 ADR-0020 让开头每回合一样。
- **轮数**：仍是 `MAX_TOOL_ROUNDS = 1`，一轮里可以同时看几样。已经预先回忆了剧情的回合仍然禁止查看（照旧），这种回合里问天气的少见，不为它破例。最后一轮附在结果后面的话分开写：回忆剧情照旧用 `LAST_ROUND_NOTE`；看天气、翻日程用实验里的「（这一轮不能再调用任何工具了，请现在就回答制作人。可以像看了一眼手机那样自然地说，不要提到工具或记录。）」。
- **工具标记漏进回复**：实验里有 1/20 次，模型在允许查看的那一轮把 DeepSeek 自己的调用标记（`<｜｜DSML｜｜ …`）当文字写出来，回复里没有正常台词。引擎要保证这类标记永远不推给用户、不送去合成：认出来以后丢掉这一轮的文字，再问一次；还是这样，就按现在的「没有返回任何内容」让回合失败。认的规则只看服务商自己的调用标记前缀，普通台词里不会出现。
- **「正在查看」事件**：回合的事件流里加一种事件，引擎开始执行这一轮的查看时发一次，带这一轮看的是哪几样（`weather`、`schedule`、`story` 的列表），没给的、认不出的查看不算进去。它只在 `delta` 之间出现，不存，不进对话记录和运行记录。通话复用同一种事件（通话事件本来就包含回合事件）。前端类型、`liveConversation` 的状态里加「她正在看什么」，收到下一个 `delta`、`done` 或 `error` 时清掉。
- **界面**：
  - 对话里：她那条还没有字的回复，把转圈旁边写上「真乃正在看天气」；已经有字的，在字下面加一行同样的小字。几样一起看时连起来写，如「真乃正在看天气、翻日程」。文案只有「看天气」「翻日程」「回忆」三个词，进 `zh.ts`。读屏器用礼貌模式播报。
  - 通话层：在现在显示「正在听你说」那一行的位置显示同样的提示，规则一样。
  - 不加音效、语气词或别的填充。
- **ADR**：新写一条，记下「她平时不知道、要看了才知道」的取舍：要她主动说的推（天气能主动提时、正在做的工作），被问到才说的让她自己看（天气、日程）。对比过的做法有三种：全推（现状）、全让她看（会失去主动关心）、推和看混用（选了这个）。代价是被问到的回合多一轮模型首字，还有服务器要记每段往来推过没有。顺带说明搭话为什么不改。
- **GLOSSARY**：改「此刻」：打字和通话时日程只带正在做的那项，天气只在能主动提时带、一段往来里一边一次，其余她要查看。新加「查看 (Look-up)」：她在回合里自己去看天气、翻日程或回忆剧情；用户能看到她正在看什么；不存，不是对话事件。`_Avoid_`：工具调用、函数调用。

## Testing Decisions

- 好的测试只看外部行为：发一个回合，看模型拿到的提示词里有什么、给了哪些查看、查看返回什么、事件流里出现什么、用户最后看到什么。不测内部函数怎么拼字符串，不断言整段提示词全文。
- **后端：文字回合接口**（`tests/test_text_turn.py` 的 `send_turn`，加脚本化的 `FakeLLM`）。照 `test_recall_story.py`（模型按剧本发出调用、拿到结果再答）、`test_producer_weather.py`（断言「此刻」里有没有天气、哪句能不能主动提）、`test_schedule_she_knows.py`（她知道哪些日程）的写法。要覆盖：
  - 打字时「此刻」没有本周其余和下周的日程，有正在进行的那项；
  - 模型翻日程，拿到整段日程；看天气，拿到两边的天气、没有「能不能主动提」那句；天气取不到时拿到「看不到」；
  - 能主动提的回合「此刻」里有天气和「提一次」那句；同一段往来的下一回合没有；隔了 `LONG_APART` 以后又有；一边能提、一边不能时只推能提的那边；
  - 提示句跟着开关变：日程关了不提日程、没有翻日程；没有天气不提天气、没有看天气；
  - 查看列表在开关不变时每回合一样；
  - 事件流里，查看前有「正在查看」事件，带对的几样；没给的查看不发；
  - 模型把调用标记写成文字时，用户收不到它，引擎再问一次；两次都这样时回合失败；
  - 搭话、光顾、朋友圈的「此刻」不变（现有测试照旧通过）。
- **后端：通话回合**（`tests/test_call_turns.py` 那一套）：通话里一样能查看、发「正在查看」事件；打断时正在进行的查看一起取消（照 `call-turn-taking` 票 02 的测试）。
- **前端：`liveConversation`**（`liveConversation.test.ts` 的写法，喂事件、看状态）：收到「正在查看」后状态里有她在看什么，收到下一个 `delta`、`done`、`error` 后清掉；通话那边同理。不写组件渲染测试。
- **本地验收**：照 `docs/agents/local-acceptance.md`，在本地构建版上用 Playwright 和真模型，文字聊天和通话各问一次天气、一次日程，看到提示出现又消失，回复里没有标记；截图附在票里。
- 改了查看的描述、提示句或最后一轮那句，要在真模型上重跑一次实验脚本的「被问到」场景（`research/on-demand-context` 分支上的 `experiment.py`），确认 5 个问题都调了对的查看。

## Out of Scope

- 城市、角色和同伴的生日、节假日、往年今天的演出、周期、动态、好感度：照旧放进「此刻」。
- 搭话、光顾、朋友圈的「此刻」不变，也不给查看。
- 查别的城市、查明天以后的天气：以后可以加成新的查看，这次不做。
- 预先回忆（检索在回合开始前替她回忆剧情）时显示「正在回忆」：那是检索的一部分，不是她在回合里去看，这次不显示。
- 通话里查看时的音效、语气词填充。
- 把查看记进运行记录、看板统计。
- 把「推过天气」存进数据库。
- 调整 `MAX_TOOL_ROUNDS`，或允许已经预先回忆的回合再查看。

## Further Notes

- 实验只测了真乃一个角色、文字聊天，没测通话；本地验收时通话那一遍顺便看延迟是否能接受。
- 实验里能主动提天气的那天，两种做法各有一次把「晚些时候下雨」说成正在下或明天下。这是现在就有的问题，这次不处理。
- 实验里被问东京天气时，现在的做法两次把「多云」说成「阴天」，按需的 4/4 对。看来数据刚查到、离回答近，模型更不容易说错。
- 自带 LLM 的保存检查和启动检查已经要求模型支持工具调用，不用为查看另加检查。
