# 02: 到了日子的信

**What to build:** 制作人生日那天，和他最亲近的那位给他写一封信；她过生日那天（她在亲近以上），给他写一封谢谢他的信；认识她满 100 天、之后每满一年，她写一封纪念的信。这些信在制作人那边的那一天一开始就写好，他那天打开网站时已经在列表里。很久没来的制作人不会收到，错过的日子也不补。写信偶尔失败时会自己重试，用户看不到。

见 spec「场合和条件」「写信的循环」。

**Blocked by:** 01

**Status:** done

- [x] 每一遍先给每位用户排一次今天（制作人档案时区，没填用 `Asia/Shanghai`）到了日子的场合，同一天只排一次；后端在当天任何时候起来都会排上当天，停机跨过的日子不补。
- [x] 制作人生日：档案里有生日、今天是他的生日（2 月 29 日平年算 2 月 28 日，用现有的判断）；只有一位写：有过回合、至少信任、不在冷却中的角色里档位最高的，同档比全部时间的回合数，再按角色顺序；没开好感度的部署只比回合数。没填生日不写。
- [x] 她的生日：今天是她的生日，她在亲近或以上才写。
- [x] 相识纪念：从和她第一个回合那天（含导入的对话）算起满 100 天，或之后每年同月同日；她在信任或以上才写；2 月 29 日同上。
- [x] 这三种只写给最近 30 天有过回合或接通过通话的制作人（30 天是代码常量）；升档、集齐不受这条限制。
- [x] 和升档、集齐撞在同一天时合成一封，信里把几个场合都写到；已经写过信的顺延到第二天（01 的规则对这几种同样成立）。
- [x] 写信失败（模型出错、解析不出）时隔一阵重试，最多 3 次（间隔是代码常量），每次一条失败的运行记录，3 次后放弃；用户看不到。
- [x] 要写的信的日子过去一天以上还没写出来的作废。
- [x] 测试推进假时钟到那一天再调「写一遍」；第一个回合、最后一次往来照先例直接改库里的时间；照 `test_reach_outs.py`、`test_producer_profile.py` 里生日的测试。

- 「每一遍先排今天到了日子的场合」加在 `Letters.run_due` 里写之前；`happened` 记的是 `due_at = now`，到了日子的照这样记即可。
- 现在失败直接删（`_drop`），`letters_due.attempts` 列已经有了，重试改这里；过期在 `_due` 或写之前判断。

### 实现说明（票 02）

- **场合**：`letter_prompt.Occasion` 加 `her_birthday`、`producer_birthday`、`anniversary`，`OCCASIONS` 接在集齐后面（她的生日、制作人生日、相识纪念）；`_OCCASIONS` 里相识纪念带 `{since}`，由 `_since` 按「第一次说话那天」和写信那天算成「满 100 天」「满一年」「满 N 年」（按 365 天取整，顺延一天也不会算错）。前端 `Occasion` 和 `copy.letter.occasions` 跟着加（她的生日、你的生日、相识纪念）。
- **排期**：`Letters.run_due` 在写之前先调 `_unplanned`：用 `read_in_touch`（不含封禁）找最近 `ACTIVE`（30 天）里有过回合或接通过通话的用户，按档案时区（没填用上海）算今天，没排过的用 `_come_round` 算出今天到了日子的场合，`_keep_plan` 写进 `letters_due`（`due_at` 为现在），同时在新表 `letter_users.planned_day` 记下这一天排过了（登记进 `USER_DATA`）。总开关关着、或者没有对话模型时不排，所以关着和停机跨过的日子都不补。
- **谁写**：她的生日要好感度开着、亲近以上；相识纪念要和她有过回合，从她所有对话里最早一条消息那天（含导入的）算起，满 `ANNIVERSARY_DAYS`（100）天或之后每年同月同日（2 月 29 日走 `is_birthday`）；制作人生日在有过回合、不在冷却、至少信任的角色里比 `(档位, 回合数, 角色顺序)`，好感度关着时档位一律按信任。冷却中、冷淡、疏远的角色什么场合都不排。
- **合并**：`_due` 改成只要一组（同一位角色、同一天）里有一条到了时间，就把这一组全取出来，所以退避中的信和新来的场合会合成一封。
- **重试**：失败时 `_failed` 给每条 `attempts + 1`，`due_at` 推到 `RETRIES`（10、30、60 分钟）里对应的那个之后；三次重试都用完还失败才删。「最多 3 次」按「重试 3 次」读，所以最多试 4 次、留 4 条失败记录。
- **过期**：`_write` 读完状况后，制作人那边的今天比信的日子晚一天以上（`KEPT`）就作废，在顺延的判断之前。
- **判断**：
  - 新加了第 4 张表 `letter_users`：不记下来就分不出「排过了、今天没有场合」和「还没排」，重启、关了再开都会重排。规格「存储」只写了三张表。
  - 很久没来的制作人在某个纪念日当天来聊了一句，下一遍就会给他排上当天的信。字面上符合「最近 30 天有过回合」，没有另外排除。
  - 制作人当天先排过、之后才在档案里填上今天是生日，这一天不会再排。
  - 重试按每条要写的信分别计次；退避中的组来了新场合会立刻整组再写，失败记录可能比 4 条多。
  - 列表上的相识纪念统一叫「相识纪念」，不分 100 天还是第几年。
- **审查**：规格和标准两份审查做了这些改动：顺延后纪念信的「满几年」改成按天数取整、排期时某位用户读出错只跳过他并写日志、删一行不走新分支的参数、删一句重复的断言、`_RANKS` 补注释。没改的判断题：几处 `list[tuple[...]]` 没抽成数据类；加一种场合要改六处（前端那两处有 `satisfies` 兜着）。
