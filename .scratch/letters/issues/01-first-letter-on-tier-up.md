# 01: 走通一封升档的信

**What to build:** 部署者在后台打开「信」以后，制作人和某位角色的好感度第一次升到亲近（或亲密），或者集齐这位角色，过一会儿她就写好一封信。制作人点对话列表页首的信封键，在所有的信的列表里看到这封信，点了整屏出现她的信封，拆开以后她的字一个一个写在信纸上，每段写完淡出中文字幕，信末写上她的名字，点「收好」收起来，信飞回信封键。读过的信换一台设备也算读过。

这一票没有语音（03）、配乐（04）、签名图（06，信末先用信上的字体写她的名字），也不做弹出、她的对话页的入口、删除和按月分组（05）；到了日子才写的信在 02。时间先按字数估。见 spec「场合和条件」「存储」「写信的循环」「写一封信」「接口」「前端」「后台设定和看板」。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 后台设定多一项「信」，只有总开关，默认关，`.env` 的 `EIDOLON_LETTERS` 可以开；在配置页「限额与玩法」标签，搭话后面。关着时什么信都不写，关着时发生的升档和集齐以后也不补。
- [x] 三张新表（信、信的语音、要写的信）建好、登记进用户数据，随删号删除；旧库启动时自动建表。信的语音这一票还不写入。
- [x] 好感度第一次升到亲近、第一次升到亲密、集齐这位角色时（成就里同一处判定），在同一个事务里记一条要写的信；掉下去再升回来不再记；成就上线时的补算不记。
- [x] 后端启动时起常驻循环，每分钟把到了时间的要写的信写出来；测试推进假时钟后直接调「写一遍」。写之前再查：总开关、她在冷淡/疏远/冷却中、封禁、限额为零，不满足的作废。
- [x] 同一位角色、同一天（制作人档案时区，没填用 `Asia/Shanghai`）的几个场合合成一封；她今天已经写过信的，新场合顺延到第二天。
- [x] 写信用部署者的对话模型（自带 LLM 的用户也一样），请求照 spec「写一封信」：设定和经历全文、制作人资料、档位语气、「你们之间的事」（第一次说话的日子、回合数只当背景、她自己来源的最近 30 条记忆）、跨对话最近 60 条消息、最近 3 封信、写信的规矩和场合。
- [x] 解析出抬头和各段；出处不存；中文里的语气提示剥掉；正文去掉语气提示后超过 330 字重写一次，还超照样用；解析不出算失败（这一票失败先不重试，重试在 02）。
- [x] 每封信一条「信」运行记录（成功、失败、角色、服务调用、用量），「用了自带密钥」为否；回合趋势、限额等按种类计数的地方不把它算进去。
- [x] 接口：信的列表（id、角色、场合、写信那天、读没读过、弹没弹过，从新到旧）、读一封（抬头、各段去掉语气提示、签名替代文字；语音和配乐字段先为空）、标读过；别人的信一律 404。账号多一个字段说部署者开没开信；没开也没有信的用户看不到入口；关掉总开关后已有的信照样能看。
- [x] 前端：对话列表页首、服务状态旁一个信封键，有没读过的信时带点；点开是能滚动的列表（电脑浮层、手机底部抽屉），每行她颜色的小信封、名字、场合、日期，从新到旧。拆信这一层照 `last-letter` 分支的信件层重写（整屏压暗、信封、拆开、逐字写、字幕淡出、跳过、读完「收好」、收起飞回信封键、减少动态效果时直接整封），信纸信封固定浅色，字体用 `next/font/google` 的 Klee One、不预载。拆开即标读过。
- [x] 时间轴是纯函数（字、估出的每块起止 → 每个字的时刻、签名时刻），有单测；它的输入留出「每块的实际时长」，03 接上语音时用。
- [x] 后端测试走 `make_client` + `FakeLLM`，升档和集齐靠现有的回合、送礼接口触发；照 `test_reach_outs.py`、成就的测试、`test_activity_records.py`、`test_database.py`。
- [x] 本地构建版上用 Playwright 看一遍：造一次升档，「写一遍」后在列表里拆开这封信，电脑和手机各截一张（`docs/agents/local-acceptance.md`）。

## Comments

### 实现说明（票 01）

- **后端**：新模块 `letters.py`（`Letters`：`happened` 在成就的事务里记要写的信，`run_due` 是「写一遍」，`keep_writing` 每分钟一次；`listed`、`letter`、`mark_read` 给接口用）和 `letter_prompt.py`（`LetterMaterial` → 请求、`parse_letter`、`Written.length`）；`letters_api.py` 三个接口 `/api/letters`、`/api/letters/{id}`、`PUT /api/letters/{id}/read`。
- **接到成就上**：`Happenings` 多一个参数 `letters`（`LetterOccasions`），`_happened` 在给完奖励后把这次**新**给出的「好感度档位」第 1、2 阶段和「集齐」告诉它；成就上线时的补算走 `reward_everyone`，不经过这里，所以天然不记（有测试）。
- **后台和账号**：`LiveConfig.letters_on`、`_Letters` 一项、`EIDOLON_LETTERS`、`LettersInput`；账号多 `letters`（部署者开没开）。运行记录多一种 `letter`，按种类计数的地方本来就是点名 `turn`/`call` 的，不用改。
- **三张表**：`letters`（场合存 JSON 数组，各段存带语气提示的日语和剥过语气提示的中文）、`letter_voices`（这一票不写）、`letters_due`（`attempts` 这一票不用）；登记进 `USER_DATA`。时间一律存 UTC 的 ISO 字符串，按字符串比较。
- **判断**：
  - 关着总开关时，`run_due` 把所有要写的信删掉（「关着时发生的以后也不补」）；没有对话模型时什么都不做、不删。
  - 顺延放在写的那一刻判断：这位角色这一天已经有信，就把这几条改到第二天、制作人那边的 0 点。
  - 超长重写：第二次解析不出或者模型出错，用第一次的。
  - 档位语气：场合里有亲密用亲密、有亲近用亲近，否则用写信时的档位；好感度关着时不带。
  - 「回合数」用她和制作人所有对话里用户消息的条数（和成就上线时数回合一样）。
  - 对话记录里她的话用 `messages.ja` 去掉语气提示，制作人的用 `text`；日期按制作人时区。
- **前端**：`lib/letter.ts`（类型、`showsLetterButton`、`hasUnread`、`letterDay`、时间轴 `partsOf(letter, durations?)`）；`components/letter/` 下 `LetterProvider`（外壳持有列表和正在拆的那封，载入和切回标签页时拉列表）、`LetterButton`（页首键，宽屏 Popover 固定高度、窄屏 90dvh Drawer）、`LetterLayer`（照 last-letter 重写，去掉音频；Klee One 走 `next/font/google`、不预载，跟拆信层一起懒加载）、`Seal`。CSS 变量、`letterVars`、对话框 `letter` 变体、按钮 `letter` 变体、对比度测试照 last-letter 搬过来。
- **验收**：本地构建版上用真的对话模型走了一遍：好感度设到 64.99 后聊一句升到亲近，循环一分钟内写好信；电脑、手机从页首信封键的列表拆开、逐字写、字幕、签名、「收好」飞回，减少动态效果时直接整封；读完点消失。验收用户已删。
- **审查**：标准和规格两份审查的修改已做（注释错位、测试合并、`font-sans` 进按钮变体、场合文案按 `Occasion` 定型、`_Standing`、补「以前的信」的断言、GLOSSARY「运行记录」）。没改的判断题：右上角小点和「宽屏 Popover、窄屏 Drawer」的写法在几处重复，没抽组件；330/280/300 三个数分在常量和提示词里。
